# 凌美会ホームページ 管理画面（homepage-cms）— 引き継ぎ資料

凌美会のホームページは、2つのリポジトリでできています。

| リポジトリ | 役割 |
|---|---|
| **homepage-cms**（この資料） | 部員がホームページの内容を編集・公開する**管理画面**。Google Apps Script（GAS）で動く |
| [homepage](https://github.com/ryobi-art-club/homepage) | 管理画面で保存された内容から**公開サイト**を作り、GitHub Pages で公開する |

この資料は、システム全体の引き継ぎ資料を兼ねています。サイト側だけの話は homepage の README にあります。

## 1. システムの全体像

```
部員のブラウザ
    │  管理画面の URL を開く（Google アカウントでのログインが必要）
    ▼
管理画面（homepage-cms / Google Apps Script）
    │  確認コードのメールでログイン（許可リストに載っている人だけ）
    │
    ├── 内容の保存 ─────────→ コンテンツ用スプレッドシート
    ├── 画像の保存 ─────────→ Google Drive（種類ごとのフォルダ）
    ├── 目録の読み取り・誤字チェック → Gemini API
    └── 「公開する」 ────────→ GitHub Actions を起動
                                 │
                                 ▼
                      公開サイトのビルド（homepage リポジトリ）
                         スプレッドシートと Drive を読み取り専用で読み、
                         HTML を作って GitHub Pages に公開
                                 │
                                 ▼
                      https://ryobi-art-club.github.io/homepage/
```

- **データの置き場所はスプレッドシートと Drive だけ**です。管理画面にも公開サイトにも、データベースのようなものはありません。
- **公開サイトは「公開する」を押したときにだけ作り直されます。** 定期的な自動更新はありません。押してから数分で反映されます。
- 管理画面での「下書き保存」は、スプレッドシートの内部用のシートに保存するだけで、公開サイトには影響しません。
- 公開サイトに出るのは、管理画面で「公開中」になっている項目だけです。

**管理画面で編集できないもの**：サイトの固定の文章（紹介文、活動場所、年間スケジュール、連絡先など）、ロゴ、デザインです。これらは homepage リポジトリの `src/` を直接編集します（homepage の README の「固定の文章や画像を変えるとき」）。

## 2. アカウントと権限

このシステムの権限は、管理を簡単にするため、なるべく少ないアカウントに集めています。

- **開発用の Google アカウント（1つ）**：Google 関係のもの（GAS、スプレッドシート、Drive、Google Cloud、Gemini）はすべてこのアカウントが持っています。
- **サービスアカウント（1つ）**：公開サイトのビルドが、スプレッドシートと Drive を読むためだけに使います。開発用アカウントの Google Cloud プロジェクトの中にあり、IAM の画面から管理できます。
- **GitHub の組織 `ryobi-art-club` のオーナー**：管理者の個人の GitHub アカウントです。

> **このリポジトリは公開されています。** 具体的なアカウント名・メールアドレス・パスワード・鍵は、ここには書かないでください。引き継ぎのときに、管理者から後任へ直接渡します。

| もの | 何に使うか | 持ち主 | 備考 |
|---|---|---|---|
| GAS プロジェクト（管理画面） | 管理画面そのもの。**このアカウントの権限で**シート・Drive の読み書きとメール送信をする | 開発用の Google アカウント | 設定値は GAS エディタの「スクリプト プロパティ」（[8-3](#8-3-script-properties設定値)） |
| コンテンツ用・許可リスト用のスプレッドシート | ホームページの内容、管理画面にログインできる人の一覧 | 開発用の Google アカウント | サービスアカウントにも閲覧権限を共有している（コンテンツ用） |
| Google Drive の4つのフォルダ | 画像の置き場所（新歓・活動記録・展示会・ご依頼） | 開発用の Google アカウント | サービスアカウントにも閲覧権限を共有している |
| Google Cloud プロジェクト | サービスアカウントと、その鍵の管理 | 開発用の Google アカウント | 鍵（JSON）は homepage リポジトリの Actions のシークレットに登録。鍵ファイルはリポジトリに入れない |
| Gemini の API キー | 目録の読み取りと誤字チェック | 開発用の Google アカウント | スクリプト プロパティ `GEMINI_API_KEY` |
| GitHub の組織と2つのリポジトリ | ソースコード、GitHub Actions、GitHub Pages | 管理者の GitHub アカウント（組織のオーナー） | |
| GitHub App（`Ryobi-Homepage-Deployer`） | 管理画面が GitHub Actions を起動するため（`GH_AUTH_MODE` は `APP`） | GitHub の組織（組織のオーナーが管理） | 組織に「インストール」して使う。App ID・インストール ID・秘密鍵はスクリプト プロパティにある |
| エラー通知の宛先 | システム側のエラーが起きたときのメール | 管理者が受け取れるアドレス | スクリプト プロパティ `ERROR_NOTIFY_EMAIL`（任意） |

### 引き継ぎのときに渡すもの

1. **開発用の Google アカウント**：ログイン情報と、2段階認証の手段（バックアップコードを含む）。復旧用のメールアドレスや電話番号が前の管理者の個人のものなら、後任のものに変えてもらう。
2. **GitHub の組織のオーナー権限**：後任の GitHub アカウントを、組織のオーナーに追加してもらう。
3. **GitHub App**（`Ryobi-Homepage-Deployer`）：組織 `ryobi-art-club` の持ち物なので、オーナー権限を渡せばそのまま使える。渡す側も受け取る側も、特にすることはない。
4. **エラー通知の宛先**：スクリプト プロパティ `ERROR_NOTIFY_EMAIL` を後任のアドレスにする。

サービスアカウントの鍵やスクリプト プロパティの値は、開発用アカウントでログインすれば見られる（作り直せる）ので、個別に渡す必要はありません。

**代わりがいない状態を避ける**：権限を1人に集めていると、その人が急に対応できなくなったとき、誰も直せなくなります。GitHub の組織のオーナーはもう1人（次の管理者の候補など）にも付けておき、開発用アカウントの復旧手段も、特定の個人だけに結びつけないようにしておくと安心です。

### 持ち主のアカウントが使えなくなると止まる

管理画面は「デプロイした人」のアカウント（今は開発用の Google アカウント）の権限で動きます（`appsscript.json` の `executeAs: USER_DEPLOYING`）。そのアカウントが使えなくなると、管理画面は動かなくなります。確認コードのメールも、このアカウントから送られています。

- 持ち主は、個人の大学アカウントではなく、今のように**部で管理する開発用のアカウント**にしておきます。卒業で大学のアカウントが消えると、管理画面が止まってしまうためです。
- やむを得ず持ち主のアカウントを変えるときは、GAS プロジェクト・スプレッドシート・Drive フォルダの持ち主を新しいアカウントに移します。そのあと、新しいアカウントで管理画面をデプロイし直してください（[4-5](#4-5-本番に反映するバージョンの切り替え)）。デプロイし直して管理画面の URL が変わった場合は、ヘルプページ（`docs/index.html`）の中のリンクと、部員への案内も直します。
- サービスアカウントにスプレッドシートと Drive フォルダが共有されたままか、移したあとに確認します（共有が外れると、サイトのビルドが失敗します）。

## 3. ふだんの運用

### 部員を追加する・外す

許可リスト用スプレッドシートの `allowlist` シートに、1人1行で書きます。

| name | email |
|---|---|
| 部員の名前 | メールアドレス |

- `name` は、管理画面の「ログイン中」や公開履歴に表示されます。
- 外すときは行を消します。すでにログイン中の人は、ログインの有効期限（現在の設定で180分）が切れるまで使えます。
- 管理画面のログインは「Google アカウントでのログイン」と「確認コード」の2段階です。Google アカウントは何でもよく、許可リストに載っているかどうかは確認コードを送るメールアドレスで判定します。

### 年度替わりにすること

- [ ] 許可リストを更新する（新しい担当者を追加、卒業生を外す）
- [ ] 管理画面の「入部希望の方」で、新しい年度を追加する
- [ ] 管理者が交代するなら、[2. アカウントと権限](#引き継ぎのときに渡すもの)の「引き継ぎのときに渡すもの」を行う
- [ ] [5. 定期的な点検](#5-定期的な点検)をひととおり行う

### エラーの通知メールが届いたら

`ERROR_NOTIFY_EMAIL` を設定していると、システム側のエラー（設定の不備、GitHub との連携の失敗、Google の利用上限など）が起きたときに、メールが届きます。部員が画面からコピーして送ってくる報告文も、同じ形式です。

1. メールの「操作」と「内容」を見て、[7. トラブルシュート](#7-トラブルシュート管理者向け)の表で原因を探します。
2. 詳しい記録は、GAS エディタの「実行数」画面にあります（エラーは `console.error` で記録されます）。日時とエラー ID で探せます。
3. 「公開」のエラーでも、**内容はスプレッドシートに保存済み**のことが多いです（GitHub の起動だけが失敗した場合など）。原因を直したら、もう一度「公開する」を押せば反映されます。

### Drive の容量

管理画面のホームに「Drive容量」が出ます。残りが少なくなると、色が変わり、容量を空けられる候補（古い展示会のフォルダなど）が表示されます。

- 展示会で使わなくなった画像は、自動では消さず、非公開の `CMS_未登録_…` フォルダに移しています。不要と確認できたら、Drive で手で削除してください（[8-6](#8-6-google-drive-のフォルダ構成)）。
- 容量は、GAS プロジェクトの持ち主のアカウント全体の容量です（ホームページ以外のファイルも含みます）。

## 4. 変更とデプロイ

### 4-1. 準備（最初に1回）

- **Node.js**（テストとプレビューに使う）
- **clasp**（GAS のコードを手元から送る道具）
  ```bash
  npm install -g @google/clasp
  clasp login   # GAS プロジェクトを編集できる Google アカウントでログイン
  ```
- プレビューの撮影を使うなら、**Google Chrome** と、`npm install --prefix tools/preview`

### 4-2. テスト

```bash
cd homepage-cms
node --test tests/*.cjs
```

Google には接続しません。保存形式、展示会の画像の扱い、目録の読み取り、誤字チェック、エラーの通知、会期表示などを確かめます。

### 4-3. 画面の確認（プレビューと撮影）

管理画面の見た目や動きは、GAS に送る前に手元のブラウザで確認できます。サンプルデータを使い、Google には接続しません。詳しくは [`tools/preview/README.md`](tools/preview/README.md)。

```bash
node tools/preview/build.cjs     # tools/preview/out/preview.html を作る
node tools/preview/shoot.cjs     # 全機能を動かして撮影（任意）
```

`shoot.cjs` は、ログインから公開までのボタンをひととおり押し、崩れやすい画面を撮影します（`tools/preview/out/shots/`）。最後に次の内容を表示します。

- 画面が横にはみ出していないか（スマホ・タブレット・横向きの各サイズ）
- 画面の中で JavaScript のエラーが起きていないか
- `UiScript.html` の関数のうち、一度も動かなかったもの（機能を足したら、ここに出ないよう撮影の手順も足す）
- Excel 読み込み用のライブラリ（SheetJS）を、整合性チェック付きで読み込めたか

### 4-4. GAS に送る

```bash
cd homepage-cms
clasp push
```

`clasp push` で変わるのは**テスト用の版だけ**です。部員が使っている本番の管理画面は、まだ変わりません。

- テスト用の版は、GAS エディタの「デプロイ」→「デプロイをテスト」の URL（末尾が `/dev`）で開けます。
- `.claspignore` に書いたもの（`tests/`、`tools/`、`docs/`、README など）は送られません。

### 4-5. 本番に反映する（バージョンの切り替え）

GAS エディタで「デプロイ」→「デプロイを管理」→ 本番のデプロイを選んで「編集」（鉛筆）→ バージョンを「新バージョン」にして「デプロイ」。

- **管理画面の URL は変わりません。** 部員は再読み込みするだけで新しい版になります。
- 「新しいデプロイ」を作ると URL が変わってしまうので、ふだんは使いません。

### 4-6. 元に戻す

同じ「デプロイを管理」→「編集」で、バージョンに**前の番号**を選んで「デプロイ」します。コードを戻す必要はなく、すぐに元の版に戻ります。

### 4-7. 公開サイト側を変えたとき

homepage リポジトリに push しても、サイトは自動では作り直されません（GitHub Actions は「公開する」か手動実行でだけ動きます）。push のあと、次のどちらかで反映します。

- 管理画面で「公開する」を押す
- GitHub の homepage リポジトリの「Actions」→「Build and Deploy Ryobi Site」→「Run workflow」

### 4-8. 両方を変えるときの順番

スプレッドシートに列を足すなどの変更は、**古いコードでも新しいコードでも読めるように**作っています（列は末尾に足し、使わなくなった列もすぐには消さない）。そのため、管理画面とサイトのどちらを先に反映しても壊れません。新しく変更を加えるときも、この考え方を守ってください。

## 5. 定期的な点検

年度替わりなど、1年に1回くらいを目安に確認します。

| 項目 | 確認すること | 方法 |
|---|---|---|
| SheetJS（Excel の目録の読み込み） | 新しい版が出ていないか | [cdn.sheetjs.com](https://cdn.sheetjs.com/) を見る。版を上げるときは `UiScript.html` の `SHEETJS_URL` と `SHEETJS_INTEGRITY`（整合性チェックの値）を一緒に変える。整合性チェックの値は `curl -s <URL> \| openssl dgst -sha384 -binary \| openssl base64 -A` の結果の頭に `sha384-` を付けたもの。変えたら `shoot.cjs` で読み込めるか確かめる |
| Font Awesome（アイコン） | 古すぎないか | 管理画面の `Ui.html` と、サイトの `build_site.py` で 6.4.2 を使っている |
| Gemini のモデル | 提供が終わっていないか | 目録の読み取りや誤字チェックが「モデルが見つからない」などで失敗したら、スクリプト プロパティ `GEMINI_MODEL` を新しいモデル名にする |
| GitHub App | 使える状態か | 今は GitHub App を使っているので、トークンの期限切れはない（管理画面が毎回、短時間だけ使えるトークンを作る）。App の秘密鍵を作り直したら、スクリプト プロパティ `GH_PRIVATE_KEY` も新しいものにする |
| Python のライブラリ（サイト側） | 大きな版上げが出ていないか | homepage の `requirements.txt` は大きな版上げで壊れないよう上限を付けている。上限を上げるときは手元でビルドを確かめる |
| GitHub Actions の部品 | 古い版の警告が出ていないか | homepage の Actions の実行結果に警告が出たら、`deploy.yml` の `actions/…@v5` などを上げる |
| Drive の容量 | 残りが少なくないか | 管理画面のホーム |
| 使わなくなった列 | 片付けてよいか | 展示会のシートの `map_embed_url` は、地図の埋め込みをやめたので使っていない。しばらく問題なければ、管理画面（`Store.js` と `UiScript.html`）から扱いを外してから列を消す |

## 6. ハマりどころ

### `UiScript.html` に書いてはいけない文字列がある

`UiScript.html` は GAS の HtmlService で `Ui.html` の中に埋め込まれて配信されます。このとき、次の文字列があると `<script>` の中身が壊れ、`Uncaught SyntaxError: Invalid or unexpected token` になります。そうなると関数が1つも定義されず、「確認コードを送信」を押しても何も起きない状態になります。

- `https://`、`http://`、`//`（**`//` のコメントも書けません**。コメントは `/* */` を使う）
- `image/*`
- SVG の `xmlns="http://www.w3.org/2000/svg"`

URL は `URL_PROTOCOL + 'www.example.com/…'` のように組み立て（`URL_PROTOCOL` は `'https:' + String.fromCharCode(47, 47)`）、`image/*` は `'image/' + '*'` と分けて書きます。インライン SVG は `xmlns` なしで表示できます。

`node --test tests/*.cjs` の `ui-script.test.cjs` が、構文エラーとこれらの文字列を自動で確認します。

### スプレッドシートに書くと値が勝手に変わる

スプレッドシートは、`=` で始まる文字を数式、`2026-05-10` を日付、`001` を数字として扱います。内容のシートに書くときは、セルの書式を「書式なしテキスト」（`@`）にしてから書いています（`Store.js` の `writeSheet_`）。新しくシートに書く処理を足すときも同じようにしてください。

### `.claspignore`

GAS に送らないファイルは `.claspignore` に書きます。手元専用のファイル（Node.js 用のツールなど）を足したら、ここにも足してください。足し忘れると GAS に送られ、GAS 側でエラーになることがあります。

### スマホ表示の指定は `Code.js` にある

スマホで画面の幅に合わせて表示するための指定（viewport）は、`Ui.html` ではなく `Code.js` の `doGet()` で付けています（`addMetaTag`）。HtmlService では `Ui.html` に書いても効かないためです。プレビュー（`tools/preview/build.cjs`）でも同じ指定を足しています。

### ログインの有効期限は、操作しても延びない

ログインの有効期限（スクリプト プロパティ `SESSION_TTL_MINUTES`、現在の設定は180分）は、**ログインした時点から**数えます。操作していても延長されません。切れると「セッションが切れています」と出るので、こまめな下書き保存を部員に勧めています。

### 「公開する」で全員の下書きが消える

公開すると、その時点の内容がサイトに出るのと同時に、保存されていた下書きがすべて消えます（`clearDrafts_`）。複数人で作業するときは、公開の前に声をかけ合う運用にしています。

### 複数の Google アカウントでログインしていると開けない

部員のブラウザに複数の Google アカウントでログインしていると、「現在、ファイルを開くことができません」と出ることがあります。GAS のウェブアプリでよく知られた問題で、コードでは直せません。対処はヘルプページ（`docs/index.html`）に書いています。

### 改行コード

Windows で作業するとファイルの改行コードが CRLF になります。Git が自動で変換するので、ふつうは気にしなくて大丈夫です。スクリプトでファイルを書き換えるときは、元の改行コードを保ってください。

## 7. トラブルシュート（管理者向け）

部員向けの対処（ブラウザの操作など）はヘルプページにあります。ここは管理者が設定やコードを見て直すものです。

| 症状・エラー | 主な原因 | 対処 |
|---|---|---|
| 「確認コードを送信」を押しても何も起きない | `UiScript.html` の構文が壊れている（[6. ハマりどころ](#uiscripthtml-に書いてはいけない文字列がある)） | ブラウザの開発者ツールのコンソールでエラーを確認。`node --test tests/*.cjs` を実行し、直してから `clasp push` とバージョンの切り替え。急ぐときは前のバージョンに戻す（[4-6](#4-6-元に戻す)） |
| 「Script Properties が不足しています: …」 | スクリプト プロパティの設定漏れ | 表示された名前のプロパティを設定する（[8-3](#8-3-script-properties設定値)） |
| 「allowlist シートが見つかりません」「allowlist シートの1行目に email 列が必要です」 | 許可リストのシート名や見出しが違う | シート名を `allowlist`、1行目を `name` / `email` にする |
| 「このメールアドレスにはアクセス権がありません」 | 許可リストに載っていない | 許可リストに追加する（大文字・小文字は区別しない） |
| 確認コードのメールが届かない | 迷惑メール、または Google のメール送信の1日の上限 | 迷惑メールフォルダを確認してもらう。上限の場合は翌日まで待つ。エラーの通知メールは、確認コード用に残り20通を残して止まるようにしている |
| 「確認コードの送信回数が上限に達しました」 | 同じアドレスに1時間で5回送った | 1時間待つ。正しくログインできれば回数はリセットされる |
| 「GitHub Actions の起動に失敗しました」「installation token 取得に失敗しました」 | GitHub App の秘密鍵が違う、App が組織からアンインストールされた、App に Actions の権限がない | 内容はスプレッドシートに保存済み。App の設定とインストール先を確認し、スクリプト プロパティを直してから、もう一度「公開する」 |
| 公開したのにサイトが変わらない | GitHub Actions のビルドが失敗している | homepage の「Actions」で失敗した実行を開き、ログを見る。サービスアカウントの鍵の期限、スプレッドシートや Drive の共有が外れていないかを確認 |
| サイトに画像が出ない | 画像のファイルやフォルダが、サービスアカウントから読めない | Drive のフォルダがサービスアカウントに共有されているか確認 |
| 「Service invoked too many times」「quota」「Limit Exceeded」 | Google の1日あたりの利用上限 | 翌日まで待つ。続く場合は、大量の画像のアップロードなど原因になった操作を確認 |
| 目録の読み取りや誤字チェックが失敗する | Gemini の API キーやモデル名の問題 | `GEMINI_API_KEY` と `GEMINI_MODEL` を確認。誤字チェックが失敗しても公開は止まらない |
| 「入力が長すぎます。」 | 項目の文字数の上限を超えた | 上限は `Store.js` の各 `normalize…_` 関数にある（例：展示会の概要は1000字）。どの項目かは表示されないので、長い項目から確認する |
| 「現在、ファイルを開くことができません。」 | 複数の Google アカウントでログインしている | ヘルプページの手順を案内する |

### 8-2. 各ファイルの役割

#### `Code.js`

| 関数 | 役割 |
|---|---|
| `doGet()` | `Ui.html` をテンプレートとして評価して返す。スマホ表示の指定（viewport）もここで付ける |
| `include(filename)` | `Ui.html` の `<?!= include('...'); ?>` から呼ばれ、UiScript・UiStyles を埋め込む |

#### `Config.js`

| 関数・定数 | 役割 |
|---|---|
| `getConfig_()` | スクリプト プロパティをまとめて読む。必須の値が欠けていればエラーにする |
| `CONTENT_SHEETS` | スプレッドシートのシート名の一覧 |
| `requireString_()` / `cleanMultiline_()` | 入力の空欄・文字数のチェック |

#### `Auth.js` — ログイン

1. メールアドレスを入力 → `requestOtp(email)`：許可リストを確認し、6桁の確認コードをメールで送る。コードはそのままではなく SHA-256 のハッシュでキャッシュに保存する
2. コードを入力 → `verifyOtp(email, code)`：ハッシュを照合し、合えばセッショントークンを発行してキャッシュに保存する
3. 以降の操作では、画面がセッショントークンを毎回送り、サーバー側の各関数の最初で `requireSession_()` が確認する

| 項目 | 値 |
|---|---|
| 確認コードの有効期限 | 10分（`OTP_TTL_MINUTES`） |
| 確認コードの入力間違い | 5回で無効 |
| 確認コードの送信 | 同じアドレスに1時間で5回まで |
| ログインの有効期限 | 既定は30分、現在の設定は180分（`SESSION_TTL_MINUTES`）。ログインした時点から数える |

#### `Store.js` — 内容の読み書きと公開

| 関数（画面から呼ばれるもの） | 役割 |
|---|---|
| `getBootstrapData` | 画面を開いたときに必要なものをまとめて返す（内容、下書き、公開履歴、Drive の容量） |
| `saveDraft` / `loadDraft` | 下書きの保存・読み込み（`_Drafts` シート） |
| `previewSiteHistory` | 公開したらサイトの更新履歴がどうなるかの予測 |
| `publishState` | 公開処理（下の流れ） |

**公開処理の流れ（`publishState`）**

```
入力の確認と整形（normalizePayload_）
  → 展示会の画像を公開用のフォルダへ移し、フォルダ名と共有を整える（finalizeManagedFolders_）
  → 内容のシートに書き込む（writeStateToSheets_）
  → 前回の公開との違いを調べ、サイトの更新履歴（ChangeLog）と操作ログ（_AdminLog）に書く
  → 公開した内容の控えを保存する（_PublishedState）
  → 下書きを全部消す（clearDrafts_）、使われなくなった下書き用フォルダを片付ける
  → GitHub Actions を起動する（dispatchGithubWorkflow_）
```

Drive とスプレッドシートの更新全体は、途中で失敗してもまとめて元に戻る仕組みにはなっていません。ただし、もう一度「公開する」を押せば続きから正しい状態になるように作っています。

| 種類 | 並び順 | 必須 | 補足 |
|---|---|---|---|
| 新歓カレンダー | 年度の新しい順 | — | 公開できるのは1年度だけ |
| 活動記録・告知 | 作成日の新しい順 | タイトル | 分類は `record` / `event` / `other` |
| 展示会 | 開催予定 → アーカイブ。開催予定は開始日の近い順、アーカイブは新しい順 | 展示会名 | 会期表示は開始日・終了日から自動で作る（手入力もできる） |
| ご依頼事例 | 管理画面で並べた順 | タイトル | |

#### `DriveGateway.js` — 画像とフォルダ

| 関数 | 役割 |
|---|---|
| `getFolderMedia` / `getFolderImages` | フォルダの中の画像の一覧 |
| `uploadManagedFiles` | 画像のアップロード。項目にフォルダがまだなければ、ここで作る |
| `trashManagedFile` | 画像の削除。展示会は一覧から外すだけで、実際の移動は公開のとき。ほかの種類はすぐゴミ箱へ |

Drive の操作は、一時的なエラーに備えて最大4回やり直します（`retryDriveOperation_`）。

#### `Gemini.js` — 目録の読み取り

`extractExhibitionCatalog`：展示会の目録ファイルを Gemini に渡し、作品番号・作品名・作者名などを受け取る。

| 形式 | 渡し方 |
|---|---|
| PDF | そのまま渡す |
| 画像（JPEG / PNG / WebP / HEIC、最大20枚） | 複数枚は同じ目録の別ページとして扱う |
| テキスト（.txt / .md / .csv / .tsv / .json） | ブラウザで文字として読んで渡す |
| Excel（.xlsx / .xls） | ブラウザで SheetJS を使ってシートごとの CSV にして渡す。SheetJS は Excel を選んだときだけ、公式 CDN から整合性チェック付きで読み込む |

合計10MBまで。目録ファイル自体は保存しません。読み取った結果は画面で候補として表示し、作品画像ごとに選んだ作品名・作者名だけが保存されます。

#### `Proofread.js` — 公開前の誤字脱字チェック

- 「公開する」を押すと、公開中の文章のうち、**まだチェックしていない文章だけ**を Gemini に送ります（展示会名・サブタイトル・概要、記事と事例のタイトル・本文、更新履歴メモ）。
- 指摘があれば画面に一覧を出し、利用者が直すか、「この内容で問題ない」として公開します。自動で書き換えることはしません。
- チェック済みとして記録する（次から送らない）のは、指摘がなかった文章と「問題ない」とした文章だけで、**公開が成功したあとにだけ**記録します（`_ProofreadChecked`）。
- 約6,000文字ずつに分けて送り、2分を超えた分は次回の公開に持ち越します。Gemini が失敗しても公開は止めません。

#### `Github.js` — GitHub Actions の起動

`dispatchGithubWorkflow_()` が、homepage リポジトリのワークフローを起動します（`workflow_dispatch`）。認証は `GH_AUTH_MODE` で選びます。

- `APP`（**現在使っている方式**）：GitHub App の秘密鍵から署名付きのトークン（JWT）を作り、それと引き換えに、短時間だけ使えるトークンを毎回受け取って使う
- `PAT`：Fine-grained Personal Access Token をそのまま使う。作った人の個人のトークンで有効期限もあるため、今は使っていない

#### `ErrorReport.js` — エラーの通知

`reportError`：画面でシステム側のエラーが起きたとき、`ERROR_NOTIFY_EMAIL` にメールします（未設定なら何もしない）。

- 画面側（`UiScript.html` の `showError()`）が、エラーを「利用者が解決できるもの」と「システム側の問題」に分け、後者だけを送ります。分け方のルールは `ERROR_RULES` にあります。
- 同じエラーは6時間に1回、全体で1時間に5通まで。Gmail の残りの送信枠が20通以下なら送りません（確認コードのメールを優先するため）。
- 設定の不備で `getConfig_()` が失敗していても通知できるよう、スクリプト プロパティを直接読みます。
- 報告文にセッショントークンなどの秘密の情報は入れません。

#### `Ui.html` / `UiScript.html` / `UiStyles.html` — 画面

- サーバーの関数は `serverCall(関数名, ...引数)` で呼びます（`google.script.run` を Promise にしたもの）。プレビューでは `window.MOCK_BACKEND` に差し替わります。
- 画面の状態は `appState` にまとめています。
- エラーは必ず `showError(error, '操作名', 表示場所)` で出します。1行の要約・「詳細」で開くカード・管理者向けの報告文、の3段階で見せます。
- 文字の大きさ・余白・角の丸みは、`UiStyles.html` の先頭の値（`--fs-sm`、`--space-4` など）から選びます。文字の大きさはデジタル庁デザインシステムの日本語の基準に合わせています（本文・項目名は16px、補足も14px以上）。

### 8-3. Script Properties（設定値）

GAS エディタの「プロジェクトの設定」→「スクリプト プロパティ」で設定します。

**必須**

| 名前 | 内容 |
|---|---|
| `CONTENT_SPREADSHEET_ID` | コンテンツ用スプレッドシートの ID（URL の `/d/` と `/edit` の間） |
| `ALLOWLIST_SPREADSHEET_ID` | 許可リスト用スプレッドシートの ID |
| `ROOT_RECRUIT_FOLDER_ID` | 新歓カレンダーの画像を置く Drive フォルダの ID |
| `ROOT_ACTIVITY_FOLDER_ID` | 活動記録の画像を置くフォルダの ID |
| `ROOT_EXHIBITION_FOLDER_ID` | 展示会の画像を置くフォルダの ID |
| `ROOT_REQUEST_FOLDER_ID` | ご依頼事例の画像を置くフォルダの ID |
| `GH_OWNER` | GitHub の organization 名（`ryobi-art-club`） |
| `GH_REPO` | 公開サイトのリポジトリ名（`homepage`） |
| `GH_WORKFLOW_FILE` | ワークフローのファイル名（`deploy.yml`） |
| `GH_BRANCH` | ワークフローを動かすブランチ（`main`） |
| `GH_AUTH_MODE` | `APP`（現在）または `PAT` |

**GitHub の認証（`GH_AUTH_MODE` に応じて）**

| 名前 | 内容 |
|---|---|
| `GH_APP_ID` / `GH_INSTALLATION_ID` / `GH_PRIVATE_KEY` | `APP` のとき（現在）。秘密鍵は PEM 形式で、改行は `\n` と書く。App には homepage リポジトリの `Actions: Read and write` 権限が必要 |
| `GH_FINE_GRAINED_PAT` | `PAT` のとき。homepage リポジトリの `Actions: Read and write` 権限が必要 |

**任意**

| 名前 | 既定値 | 内容 |
|---|---|---|
| `SESSION_TTL_MINUTES` | 30 | ログインの有効期限（分）。**現在は180に設定** |
| `OTP_TTL_MINUTES` | 10 | 確認コードの有効期限（分） |
| `SITE_PREVIEW_URL` | `https://{GH_OWNER}.github.io/{GH_REPO}/` | 「サイトを開く」のリンク先 |
| `GEMINI_API_KEY` | なし | 目録の読み取りと誤字チェック。未設定なら目録の読み取りは使えず、誤字チェックはせずに公開する |
| `GEMINI_MODEL` | `gemini-3.1-flash-lite` | 使う Gemini のモデル |
| `ERROR_NOTIFY_EMAIL` | なし | エラーの通知先（カンマ区切りで複数可）。未設定なら通知せず、部員が画面からコピーして連絡する |

### 8-4. スプレッドシートの構成

シートは、最初に保存・公開したときに自動で作られます。シート名は `Config.js` の `CONTENT_SHEETS` にあります。列は1行目の見出しの名前で読むので、列の順番は関係ありません。

**内容のシート**（公開サイトのビルドも読む）

`Recruit`（新歓カレンダー）

| 列 | 内容 |
|---|---|
| `year` | 年度（例：`2026`） |
| `media_folder_id` | 画像フォルダの ID |
| `media_file_ids` | 使う画像のファイル ID の一覧（JSON。並び順どおり） |
| `published` | `TRUE` / `FALSE`（`TRUE` は1行だけ） |
| `updated_at` | 更新日時 |

`ActivityArticles`（活動記録・告知）

| 列 | 内容 |
|---|---|
| `article_id` | 記事の ID |
| `title` | タイトル（120字まで） |
| `category` | `record` / `event` / `other` |
| `body` | 本文（4000字まで。改行可） |
| `media_folder_id` / `media_file_ids` | 画像フォルダと、使う画像の一覧 |
| `published` | 公開中か |
| `created_at` / `updated_at` | 作成日時（初回公開日として表示）・更新日時 |

`Exhibitions`（展示会）

| 列 | 内容 |
|---|---|
| `exhibition_id` | 展示会の ID |
| `title` / `subtitle` | 展示会名（140字まで）・サブタイトル |
| `theme` | 概要（1000字まで。改行可） |
| `venue_name` / `venue_address` | 会場名・住所。サイトでは住所が Google マップを開くリンクになる |
| `date_line` | サイトに出す会期。ふつうは管理画面が開始日・終了日から作る（例：`2026年8月1日(土)〜8月8日(土)`）。日付で書けない会期は手入力 |
| `time_line` | 時間帯（例：`11:00〜18:00`） |
| `map_embed_url` | **使っていない**（以前の地図の埋め込み。[5. 定期的な点検](#5-定期的な点検)） |
| `display_bucket` | `upcoming`（開催予定）/ `archive`（アーカイブ） |
| `media_folder_id` | 展示会の画像フォルダの ID |
| `dm_file_ids` | DM 画像の ID（表・裏の2つまで） |
| `work_files` | 作品画像の一覧（JSON。ファイル ID・作品名・作者名・並び順） |
| `published` | 公開中か |
| `start_date` / `end_date` | 開始日・終了日（`yyyy-MM-dd`。1日だけの展示は終了日が空欄） |
| `updated_at` | 更新日時 |

`RequestCases`（ご依頼事例）

| 列 | 内容 |
|---|---|
| `case_id` | 事例の ID |
| `title` / `body` | タイトル（120字まで）・本文（4000字まで） |
| `media_folder_id` / `media_file_ids` | 画像フォルダと、使う画像の一覧 |
| `sort_order` | 表示順（小さいほど上） |
| `published` | 公開中か |
| `updated_at` | 更新日時 |

`ChangeLog`（サイトの更新履歴）：`timestamp`（公開日時）、`summary`（変更内容）、`actor_name`・`actor_email_input`（操作した人）、`revision`

**内部用のシート**（名前が `_` で始まる。サイトは読まない）

| シート | 内容 |
|---|---|
| `_Drafts` | 下書き。公開すると全部消える |
| `_PublishedState` | 前回公開した内容の控えと、そのハッシュ（変更の有無を調べる） |
| `_AdminLog` | 操作ログ（誰がいつ公開し、何を変えたか）。ホームの「公開履歴」に出る |
| `_ProofreadChecked` | 誤字チェック済みの文章のハッシュ。シートを消すと、全文章が次の公開で再チェックされる |

**下書きと控えの保存形式**：`_Drafts` と `_PublishedState` は内容を JSON でセルに保存します。1つのセルには5万字までしか入らないため、長いときは `payload_json`、`payload_json_2`、… の列に分けて保存し、読むときにつなげます。列は自動で増えます。

**シートの書き込み方**：先に全部消してから書くのではなく、範囲をまとめて上書きし、余った部分を空欄にします。公開のたびに、内容のシートの末尾の空いた行・列を片付けます。

**許可リスト用スプレッドシート**：`allowlist` シート（`Config.js` の `ALLOWLIST_SHEET_NAME`）。1行目が `name` / `email` の見出し。

### 8-5. ログインの仕組み

[`Auth.js` の説明](#authjs--ログイン)のとおりです。ほかに、GAS のウェブアプリ自体が「Google アカウントを持つ全員」に公開されているので、管理画面を開くときにも Google アカウントでのログインが必要です（`appsscript.json` の `access: ANYONE`）。

### 8-6. Google Drive のフォルダ構成

種類ごとに「ルートフォルダ」が1つずつあり（[8-3](#8-3-script-properties設定値) の `ROOT_…_FOLDER_ID`）、その中に**項目ごとのフォルダが自動で作られます**。最初に画像をアップロードしたときに作られ、公開のたびに名前が整えられます。

```
（展示会のルートフォルダ）
├── 第XX回部展_20260801              公開中の展示会（フォルダを作った日が付く）
├── 春季展覧会_下書き_20260410_1530   まだ公開していない展示会
├── CMS_下書き_{フォルダID}          公開前に追加した画像の一時置き場（非公開）
└── CMS_未登録_{フォルダID}          使わなくなった画像の退避先（非公開）
```

- 展示会の公開中のフォルダは「リンクを知っている全員が閲覧可」になり、サイトのアーカイブから「Google Drive で作品を観る」でリンクされます。非公開の展示会のフォルダは非公開になります。
- 展示会の画像は、公開中のフォルダに直接は足しません。下書き中に追加した画像は一時置き場に置き、公開のときに移します。そのため、別の下書きや公開中のサイトの画像が壊れません。
- 使わなくなった画像は、自動では消さずに退避先へ移します。不要と確認できたら、Drive で手で消してください。
- 展示会のルートフォルダ自体の共有は「制限付き」にしておいてください。

## 9. 一から作り直すときのセットアップ手順

1. **スプレッドシートを2つ作る**：コンテンツ用（中は空でよい。シートは自動で作られる）と、許可リスト用（`allowlist` シートに `name` / `email` の見出しと、最初の管理者の行を書く）。
2. **Drive にルートフォルダを4つ作る**：新歓・活動記録・展示会・ご依頼。
3. **GAS プロジェクトを用意して、コードを送る**：`clasp login` のあと、`.clasp.json` の `scriptId` を自分のプロジェクトの ID にして `clasp push`。
4. **スクリプト プロパティを設定する**（[8-3](#8-3-script-properties設定値)）。
5. **ウェブアプリとしてデプロイする**：GAS エディタの「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」。実行するユーザーは「自分」、アクセスできるユーザーは「Google アカウントを持つ全員」。表示された URL が管理画面の URL です。初回は権限の許可を求められます。
6. **公開サイト側を用意する**：homepage の README のセットアップ手順（サービスアカウントの作成、スプレッドシートと Drive フォルダの共有、GitHub のシークレット、GitHub Pages の設定）。
7. **GitHub App を用意する**：組織の「Settings」→「Developer settings」→「GitHub Apps」で App を作り（権限は `Actions: Read and write`）、homepage リポジトリにインストールする。App ID、インストール ID、秘密鍵をスクリプト プロパティに設定する。
8. **ヘルプページのリンクを直す**：`docs/index.html` の中の管理画面の URL を、新しい URL にする。

## 10. 設計の判断メモ

後任が「ここは変えてよいか」を判断するための、主な判断とその理由です。

| 判断 | 理由 |
|---|---|
| 管理画面は GAS、サイトは静的ファイル（GitHub Pages） | 費用をかけず、サーバーの管理をしなくて済むため。データはスプレッドシートと Drive に置き、部員がふだん使う Google のサービスの中で完結させている |
| サイトは「公開する」のときだけ作り直す | 部員が内容を確かめてから出せるようにするため。そのため、日付が来たら自動で何かを変える仕組み（終了した展示会の自動アーカイブなど）は入れていない。入れるなら、定期実行のワークフローを足す必要がある |
| 展示会の画像は、一時置き場と退避先を使う | 下書きを保存したり画像を外したりしても、公開中のサイトや別の下書きの画像が壊れないようにするため |
| 地図は埋め込まず、住所を Google マップへのリンクにした | 以前の埋め込み用の URL は Google の正式な方法ではなく、いつ使えなくなるかわからなかった。埋め込みはページが重く、スマホではスクロールの邪魔にもなる。部員が URL を用意する手間もなくなった |
| 会期表示は開始日・終了日から自動で作る | 同じ日付を2回入力していて、片方だけ直すと食い違っていたため。日付で書けない会期のために手入力も残し、日付を変えたら自動に戻す、という単純な決まりにしている |
| エラーは3段階で見せ、システム側の問題は管理者に通知する | 画面の1行に収めつつ、部員が管理者に正確に伝えられるようにするため |
| SheetJS は公式 CDN から、版を固定し整合性チェック付きで読む | 一般的な CDN（cdnjs）の SheetJS は古い版で止まっていて、既知の脆弱性があるため。版を固定しているので、更新は手で行う（[5. 定期的な点検](#5-定期的な点検)） |
| スプレッドシートには「書式なしテキスト」で書く | 数式や日付として解釈されるのを防ぐため（数式の注入対策でもある） |
| 文字の大きさはデジタル庁の基準に合わせた | 日本語は同じ大きさでも英語より読みにくいため。読みやすさと押しやすさ（押せる部分は44px以上）を優先した |
| 毎回は読まない説明は「？」でたたむ | 画面を広く使うため。部員向けの使い方の説明は画面の中に置き、別のマニュアルで画面を二重に説明しない |
| 部員向けのマニュアルはヘルプページだけにした | 画面の見本を含むマニュアルは、画面を変えるたびに直す必要があり、内容が古くなりやすかったため |
| 手元のプレビューはサンプルデータだけで動く | 本物のデータや Google の権限を手元に置かずに、画面の見た目と動きを確認できるようにするため |
| 公開すると全員の下書きが消える | 公開した内容と古い下書きが食い違ったまま残るのを防ぐため |
